# Developer Toolbox 重构设计

**日期：** 2026-08-24  
**项目：** lucisl.github.io 在线开发工具站

## 1. 项目目标

将现有 Hexo + Butterfly 个人博客彻底重构为一个面向开发者的在线工具站。首版只提供 JSON 格式化与时间戳转换两个工具，优先保证操作效率、视觉完成度、移动端可用性和 GitHub Pages 部署稳定性。

站点不保留博客、文章、项目展示、代码片段或关于页面。现有内容退出站点导航和构建产物，但历史文件可在实现阶段根据迁移需要删除。

## 2. 产品原则

- **本地优先：** 所有解析和转换均在浏览器内完成，不上传用户输入。
- **开箱即用：** 首屏直接进入工具工作区，无注册、无弹窗、无多余引导。
- **输入有反馈：** 成功、错误、复制和无效输入都有明确且克制的状态提示。
- **便于扩展：** 工具导航和页面结构允许未来增加编码、文本、颜色等工具，但首版不预留空功能。
- **轻量发布：** 使用原生 Web 技术，不引入运行时框架和后端服务。

## 3. 技术方案

### 3.1 架构

站点改为原生 HTML、CSS、JavaScript 静态应用，入口文件直接位于仓库根目录。浏览器直接加载页面和资源；GitHub Actions 将仓库中的站点文件上传给 GitHub Pages，不再运行 Hexo 生成流程。

```text
浏览器
  ├── 页面壳与工具导航
  ├── JSON 工具模块
  └── 时间戳工具模块
          │
          └── 本地计算，无网络请求

Git Push → GitHub Actions → 上传静态文件 → GitHub Pages
```

### 3.2 文件边界

- `index.html`：语义化页面结构、工具面板和基础 SEO 信息。
- `assets/styles.css`：设计系统、布局、组件状态和响应式规则。
- `assets/app.js`：页面导航、通知与通用交互。
- `assets/json-tool.js`：JSON 解析、格式化、压缩、错误反馈和复制交互。
- `assets/timestamp-tool.js`：时间戳识别、双向转换、时区显示和实时当前时间。
- `tests/`：使用 Node.js 内置测试运行器，对可独立调用的核心转换函数进行自动化测试。
- `.github/workflows/deploy.yml`：直接发布静态站点。

工具逻辑不依赖 DOM 的部分应导出为纯函数，便于测试。DOM 绑定只负责读取输入、调用逻辑和渲染结果。

## 4. 信息架构与视觉设计

### 4.1 页面结构

桌面端采用左侧固定导航与右侧工作区：

- 左侧包含站点标识、两个工具入口、本地处理说明和简短页脚信息。
- 右侧顶部展示当前工具名称、用途说明与状态信息。
- 主体展示当前工具工作台；同一时间只突出一个工具。

移动端将左侧导航收为顶部品牌栏和横向工具切换，工作台改为单列，主要操作保持在拇指容易触达的位置。

### 4.2 视觉语言

- 主背景使用深墨黑与略带绿色的冷灰，不使用大面积紫色渐变。
- 内容工作区使用暖白或浅灰面板，形成类似精密仪表台的明暗反差。
- 强调色采用荧光青绿色，用于主按钮、焦点、激活状态和成功反馈。
- 错误使用低饱和珊瑚红，避免与强调色竞争。
- 标题使用有性格的展示字体回退栈，正文和输入区采用高可读无衬线字体，代码与数字采用等宽字体。
- 使用细边框、网格纹理、编号标签和轻量过渡营造工具感；不使用装饰性图片或外部图片依赖。

### 4.3 可访问性

- 交互元素支持键盘操作，并具有可见焦点状态。
- 文本与背景满足清晰对比度。
- 状态信息通过 `aria-live` 向辅助技术播报。
- 不仅依靠颜色表达错误或成功状态。
- 尊重 `prefers-reduced-motion`，关闭非必要动画。

## 5. 功能设计

### 5.1 JSON 格式化

输入区和输出区在宽屏并排、窄屏上下排列。

功能包括：

- 输入 JSON 后进行解析与校验。
- 格式化输出，支持 2 空格、4 空格和 Tab 缩进。
- 压缩为单行 JSON。
- 使用示例数据快速体验。
- 复制输出与清空全部内容。
- 显示输入字符数、输出字符数和当前状态。
- 解析失败时显示可读错误信息；若运行环境提供错误位置，则同步展示位置提示。

空输入执行格式化或压缩时不生成结果，并提示用户先输入 JSON。合法的 JSON 基础值（如 `null`、数字、字符串和布尔值）也应被支持，而不只支持对象和数组。

### 5.2 时间戳转换

页面分为“时间戳转日期”和“日期转时间戳”两个紧密关联的区域，并在顶部展示每秒更新的当前时间。

功能包括：

- 输入 Unix 时间戳并转换为日期时间。
- 自动识别常见的 10 位秒级与 13 位毫秒级时间戳，同时允许用户显式切换单位。
- 展示本地时间、UTC 时间、ISO 8601 和相对当前时间的描述。
- 选择日期和时间后，同时生成秒级与毫秒级时间戳。
- 提供“使用当前时间”、复制结果和清空操作。
- 提供浏览器本地时区与 UTC 两种日期输入解释方式；默认使用浏览器本地时区。
- 拒绝非数字、非有限值或超出 JavaScript `Date` 可表达范围的输入，并显示原因。

当前时间卡片只在页面可见时持续更新，避免无意义的后台计时。

## 6. 状态与错误处理

- 初始状态提供简短示例或说明，不展示空白错误。
- 输入错误在对应区域内就近展示，并保留用户原始输入。
- 复制成功显示短暂提示；复制 API 不可用时使用兼容回退，仍失败则提供明确提示。
- 工具切换不刷新页面，并保留两个工具各自的未提交输入。
- 页面首次加载根据 URL hash 打开对应工具；未知 hash 回退到 JSON 工具。
- 不将工具输入写入 URL、日志、Cookie 或持久化存储。

## 7. 响应式与浏览器支持

- 重点验证约 1440px 桌面、768px 平板和 390px 手机宽度。
- 支持当前主流版本的 Chrome、Edge、Firefox 和 Safari。
- 核心功能不依赖实验性浏览器 API。
- 页面无横向溢出；文本区在移动端保持足够高度，按钮允许自然换行。

## 8. 测试与验收

### 8.1 自动化测试

- JSON：对象、数组、基础值、Unicode、不同缩进、压缩、空输入和非法输入。
- 时间戳：秒/毫秒识别、零和负数、日期转时间戳、本地/UTC 解释、非法数字与越界值。
- URL 工具选择：合法 hash 与未知 hash 的回退行为。

### 8.2 构建与静态检查

- 自动化测试全部通过。
- HTML、CSS 和 JavaScript 可被浏览器直接加载，不依赖构建后的隐藏产物。
- GitHub Actions 先运行测试，再从明确的发布目录上传站点文件，避免将文档、测试或旧 Hexo 源文件发布到线上。
- 检查站点标题、描述、favicon、基础 Open Graph 信息和无 JavaScript 提示。

### 8.3 视觉验收

- 桌面端与移动端分别截图检查布局、层级、对齐和溢出。
- 两个工具的初始、成功、错误和复制反馈状态均进行交互检查。
- 键盘导航顺序合理，焦点清晰可见。

## 9. 明确不做

首版不包含账号系统、云端历史记录、多人协作、服务端 API、PWA、主题切换、国际化、广告、统计追踪或除 JSON 与时间戳之外的其他工具。

## 10. 完成标准

- 站点不再呈现博客主题或博客导航，而是完整统一的在线工具产品。
- JSON 格式化与时间戳双向转换功能在桌面和移动端均可用。
- 所有数据只在本地处理，页面没有工具数据相关网络请求。
- 自动化测试通过，关键交互状态经过浏览器验证。
- 推送到 `main` 后，现有 GitHub Pages 工作流能够发布新站点。
